# Поток работы фильтров курсов

## Архитектура

Система фильтрации построена на трех уровнях:

1. **Компонент фильтров** (`item-filters.vue`) - UI и локальное состояние
2. **Composable** (`useCourseFilters.ts`) - синхронизация с URL
3. **Страница** (`pages/courses/all.vue`) - координация и рефетч данных

## Компоненты системы

### 1. item-filters.vue (Controlled Component)

**Ответственность**:

- Отображение UI фильтров
- Управление локальным состоянием (черновиками)
- Определение наличия изменений
- Эмит событий `apply` и `reset`

**Ключевые особенности**:

- Синхронизируется с props через `watch`
- `hasChanges` определяет, можно ли применить фильтры
- Enter в поле поиска вызывает `applyFilters()`
- Кнопка "Применить" отключена, если нет изменений

### 2. useCourseFilters.ts (URL State Manager)

**Ответственность**:

- Чтение фильтров из URL query параметров
- Обновление URL через Vue Router
- Преобразование между строками URL и объектами FilterOption
- Автоматический сброс пагинации при изменении фильтров

**Ключевые методы**:

- `applyFilters(filters)` - атомарное обновление нескольких фильтров
- `updatePage(page)` - обновление страницы БЕЗ сброса на 1
- `resetFilters()` - сброс всех фильтров к дефолтным значениям

**Computed значения**:

- `apiFilters` - объект параметров готовый для API запроса

### 3. pages/courses/all.vue (Coordinator)

**Ответственность**:

- Получение опций фильтров с API
- Вызов `useCourseFilters` для синхронизации с URL
- Обработка событий от `item-filters`
- Автоматический рефетч при изменении `apiFilters`

**Ключевой паттерн**:

```typescript
// Watch на apiFilters триггерит рефетч
watch(
  apiFilters,
  async () => {
    await refresh();
  },
  { deep: true }
);
```

## Последовательность действий

### Пользователь применяет фильтры:

1. Пользователь изменяет значения в `item-filters`
2. Локальное состояние обновляется (`localSearch`, `localCategory`, и т.д.)
3. `hasChanges` становится `true`, кнопка "Применить" активируется
4. Пользователь нажимает "Применить" (или Enter в поиске)
5. Компонент эмитит `apply` с объектом фильтров
6. Страница вызывает `applyFilters(filters)`
7. `applyFilters()` обновляет URL query параметры (с page=1)
8. URL изменяется → `apiFilters` пересчитывается (это computed)
9. `useAsyncData` автоматически отслеживает `apiFilters` через опцию `watch`
10. Новый API запрос с обновленными параметрами автоматически
11. Props в `item-filters` обновляются → локальное состояние синхронизируется

### Пользователь сбрасывает фильтры:

1. Пользователь нажимает "Очистить"
2. Компонент эмитит `reset`
3. Страница вызывает `resetFilters()`
4. URL обновляется до дефолтных значений
5. `apiFilters` пересчитывается → `useAsyncData` делает новый запрос
6. Props обновляются → локальное состояние очищается

## Преимущества архитектуры

✅ **Разделение ответственности**: каждый слой решает свою задачу
✅ **Контроль над рефетчем**: данные обновляются только при явном применении
✅ **URL как источник истины**: можно шарить ссылки с фильтрами
✅ **Типобезопасность**: TypeScript контролирует все типы
✅ **Оптимизация**: нет лишних запросов при редактировании
✅ **UX**: пользователь видит, что фильтры изменены до применения
✅ **SSR совместимость**: работает с серверным рендерингом
