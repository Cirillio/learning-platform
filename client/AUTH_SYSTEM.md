# Система авторизации - Обновлено

## Архитектура

### HttpOnly Cookies (безопасность)

- **Access token** и **Refresh token** хранятся только в HttpOnly cookies на бэкенде
- Клиент **НЕ** имеет доступа к токенам через JavaScript
- Токены автоматически отправляются с каждым запросом через `credentials: 'include'`

### Состояние на клиенте

- **Только User object** хранится в Pinia store (`stores/auth.ts`)
- Нет токенов в localStorage, sessionStorage или обычных cookies
- SSR: профиль загружается на сервере и передаётся клиенту через Pinia state hydration

## Компоненты системы

### 0. Auth Utils (`utils/auth.ts`)

- **Утилита `loadUserProfile()`** - универсальная загрузка профиля
- Автоматически определяет SSR или клиент
- На сервере: передаёт cookies из входящего запроса
- На клиенте: использует обычный API client с `credentials: 'include'`

### 1. Store (`stores/auth.ts`)

- **State**: `user`, `isLoading`, `error`
- **Getters**: `isAuthenticated`, `isTeacher`, `isStudent`, `userRole`
- **Actions**: `setUser()`, `clearAuth()`, `setLoading()`, `setError()`

### 2. API Client (`composables/useApi.ts`)

- `credentials: 'include'` - автоматическая отправка cookies
- Автоматический refresh на 401 (без дублирования запросов)
- Централизованная обработка ошибок

### 3. Auth Composable (`composables/useAuth.ts`)

- `login()` - авторизация + редирект
- `logout()` - выход + уведомление других вкладок
- `register()` - регистрация + автологин
- `loadProfile()` - обновление профиля
- `updateUserProfile()` - изменение данных пользователя

### 4. Server Plugin (`plugins/auth.server.ts`)

- Загружает профиль на SSR (до рендера страницы)
- **Передаёт cookies из входящего запроса в API запрос** - критично для SSR
- Передаёт состояние клиенту через Pinia hydration
- Избегает "моргания" UI при загрузке

### 5. Client Plugin (`plugins/auth.client.ts`)

- Проверяет, загружен ли профиль с SSR
- Если нет - загружает на клиенте (для SPA-навигации)
- Автоматический refresh токена каждые 10 минут (изменено с 14)
- Убрана принудительная проверка при focus - предотвращает проблемы с истекшими токенами
- BroadcastChannel для синхронизации между вкладками
- Расширенное логирование для отладки

### 6. Middleware (`middleware/auth.ts`)

- Проверяет `isAuthenticated`
- Если нет - загружает профиль через `getProfile()`
- Если failed - редирект на `/auth/login`

### 7. Guest Middleware (`middleware/guest.ts`)

- Перенаправляет авторизованных пользователей с `/auth/*` на dashboard

## Поток авторизации

### Логин

1. `useAuth().login()` вызывает `useApi().login()`
2. Бэкенд устанавливает HttpOnly cookies с токенами
3. Клиент получает `user` и сохраняет в store
4. BroadcastChannel уведомляет другие вкладки о логине
5. Редирект на `/dashboard`

### SSR (первая загрузка)

1. `auth.server.ts` выполняется на сервере
2. Загружает профиль через `getProfile()` (cookies автоматически передаются)
3. Устанавливает `user` в store
4. Pinia автоматически передаёт состояние клиенту
5. `auth.client.ts` видит загруженного пользователя и пропускает повторную загрузку

### Client-side Navigation (SPA)

1. `auth.client.ts` проверяет наличие профиля
2. Если нет - загружает через `getProfile()`
3. Middleware `auth.ts` дополнительно проверяет при переходах

### Logout

1. `useAuth().logout()` вызывает `useApi().removeToken()`
2. Бэкенд удаляет HttpOnly cookies
3. Клиент очищает store
4. BroadcastChannel уведомляет другие вкладки
5. Редирект на `/auth/login`

### Token Refresh

- Автоматически каждые 10 минут (если access живёт 15 минут)
- При получении 401 в `useApi()` - автоматический refresh + retry
- Защита от дублирования refresh через mutex
- BroadcastChannel координирует refresh между вкладками
- **Убрана принудительная проверка при смене фокуса** - предотвращает проблемы с истекшими токенами

## Синхронизация между вкладками

### BroadcastChannel события

- `login` - пользователь вошёл в другой вкладке
- `logout` - пользователь вышел в другой вкладке
- `refresh-start` - началось обновление токена
- `refresh-done` - обновление завершено

## Безопасность

### ✅ Защищено от

- XSS атак (токены недоступны через JavaScript)
- CSRF (бэкенд использует SameSite cookies + CSRF tokens)
- Token theft (HttpOnly cookies не читаются клиентом)

### ⚠️ Требования на бэкенде

- Правильная настройка CORS с `credentials: true`
- SameSite=Lax/Strict для cookies
- Secure=true в продакшене
- CSRF protection

## Troubleshooting

### HMR выкидывает на логин

- **Нормально в dev-режиме**: HMR сбрасывает in-memory state
- Профиль перезагружается автоматически через cookies
- В продакшене этого не происходит

### Профиль не загружается на SSR (401 ошибка)

**Симптомы**: В логах сервера видна ошибка 401 при `/auth/profile/`

**Причина**: Cookies не передаются с Nuxt SSR сервера на бэкенд автоматически.

**Решение**:

- Используйте утилиту `loadUserProfile()` из `utils/auth.ts`
- Она автоматически передаёт cookies через заголовок `cookie`
- Убедитесь, что все middleware используют эту утилиту

**Проверка**:

1. Проверьте логи сервера - должно быть `🍪 [Server] Cookie header: present`
2. Если `missing` - проблема в браузере или бэкенде (cookies не устанавливаются)
3. Если `present` но 401 - проверьте бэкенд (токены истекли или неверные)

### Авторизация пропадает при смене фокуса

**Симптомы**: Через 1-2 минуты после смены вкладки пользователь вылогинивается

**Причина**: Раньше при каждом фокусе на вкладке происходила принудительная проверка токена, которая могла вызвать refresh истекшего токена и logout.

**Решение**:

- Убрана принудительная проверка при focus
- Refresh происходит только по автоматическому интервалу (10 минут)
- Добавлено расширенное логирование для отладки

**Если проблема сохраняется**:

1. Проверьте консоль браузера на ошибки refresh
2. Убедитесь, что бэкенд правильно обрабатывает refresh токены
3. Проверьте время жизни access токена (должно быть > 10 минут)

## Dev vs Production

### Dev (npm run dev)

- HMR может сбрасывать состояние
- Профиль автоматически перезагружается
- Больше логов в консоли

### Production (npm run build + preview)

- Стабильное состояние без HMR
- Минимум логов
- Лучшая производительность
